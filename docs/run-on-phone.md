# اجرای اپ روی گوشی خودت (سرور = کامپیوتر خودت)

## پیش‌نیاز شبکه
- گوشی و کامپیوتر روی **یک Wi-Fi** باشند.
- IP کامپیوتر: **192.168.1.100** (اگر عوض شد با `ipconfig` ببین؛ بعد یا در
  `mobile/lib/core/config/app_config.dart` عوضش کن یا موقع بیلد
  `--dart-define=API_BASE_URL=http://<IP>:8000/api/v1` بده و دوباره بساز).

## ۱) اجرای سرور روی کامپیوتر
```bash
cd backend
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py runserver 0.0.0.0:8000
```
> `migrate` بعد از هر به‌روزرسانی کد بک‌اند لازم است (مثلاً ورود با شماره موبایل،
> مالکیت کارت، حذف نرم). اگر اجرا نشود، ورود و همگام‌سازی خطا می‌دهند.

اجازه‌ی عبور فایروال برای پورت ۸۰۰۰ (PowerShell با دسترسی Administrator، یک‌بار):
```powershell
New-NetFirewallRule -DisplayName "Django Dev 8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow
```
تست از خود گوشی: در مرورگر گوشی باز کن
`http://192.168.1.100:8000/api/v1/auth/me/` → باید یک JSON با خطای 401 بدهد.
اگر باز شد یعنی گوشی سرور را می‌بیند.

## ۲) نصب APK روی گوشی
- فایل: `mobile/build/app/outputs/flutter-apk/app-arm64-v8a-release.apk`
  (برای بیشتر گوشی‌های امروزی؛ گوشی خیلی قدیمی: `app-armeabi-v7a-release.apk`)
- روش A (کابل USB): حالت Developer + USB Debugging گوشی را روشن کن، سپس:
  ```bash
  adb install -r mobile/build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
  ```
  (adb در `C:\Users\mahdi\AppData\Local\Android\sdk\platform-tools\adb.exe`)
- روش B (بدون کابل): فایل apk را به گوشی منتقل کن (تلگرام/USB/…)، روی گوشی
  «نصب از منابع نامطمئن» را برای فایل‌منیجر مجاز کن و نصب کن.
- به‌روزرسانی روی نسخه‌ی قبلی نصب می‌شود و داده‌ها می‌مانند (دیتابیس گوشی خودکار ارتقا می‌یابد).

## ۳) کاربرها و خانواده — از پنل مدیریت
ثبت‌نام داخل اپ وجود ندارد: کاربرها را خودت در **پنل مدیریت** می‌سازی و هر نفر با
**شماره موبایل + رمز** وارد اپ می‌شود.

1. یک‌بار حساب مدیر بساز (شماره موبایل و رمز را خودش می‌پرسد):
   ```bash
   .venv\Scripts\python.exe manage.py createsuperuser
   ```
2. با سرورِ روشن، در مرورگر کامپیوتر برو به `http://127.0.0.1:8000/admin/` و با همان
   شماره و رمز وارد شو (پنل فارسی است).
3. «خانواده‌ها ← افزودن»: یک خانواده بساز (مثلاً «خانواده‌ی ما»).
4. «کاربران ← افزودن»: برای هر نفر **شماره موبایل**، **نام** (همین نام در اپ کنار
   تراکنش‌ها دیده می‌شود، مثلاً «بابا») و **رمز**؛ پایین همان صفحه خانواده‌اش را
   انتخاب کن. هر خانواده حداکثر ۳ نفر.
   - شماره را به هر شکلی بنویسی (`0912…`، `+98912…`، ارقام فارسی) یکسان ذخیره می‌شود.
   - عوض کردن رمز: صفحه‌ی همان کاربر ← زیر «گذرواژه» پیوند تغییر گذرواژه.
   - برای اینکه کسی دیگر وارد نشود ولی داده‌هایش بماند: تیک «فعال» را بردار.
5. **کاربر تست قدیمی** («کاربر تست»، ایمیلی و بدون شماره) را در «کاربران» تیک بزن و از
   منوی «عمل» حذفش کن؛ تراکنش‌های آزمایشی‌اش هم پاک می‌شوند. «خانواده تست» را هم اگر
   لازم نیست از «خانواده‌ها» حذف کن.

بعد در اپ، هر نفر روی گوشی خودش:
- با شماره و رمز خودش وارد می‌شود.
- **«تنظیمات ← فرستنده‌های پیامک بانک»**: سرشماره/نامِ فرستنده‌ی پیامک بانک‌هایش را مجاز
  می‌کند. فقط پیامک همین فرستنده‌ها ثبت می‌شود؛ هر پیامک دیگری (تبلیغ، فروشگاه، اپراتور)
  حتی با مبلغ نادیده گرفته می‌شود. صفحه از روی پیامک‌های مبلغ‌دارِ گوشی پیشنهاد می‌دهد:
  «بانک است، مجاز کن» یا «بانک نیست؛ حذف N تراکنش» (برای پاک کردن اشتباهی‌های قبلی).
  تا هیچ فرستنده‌ای مجاز نشده، هیچ پیامکی خودکار ثبت نمی‌شود.
- **«تنظیمات ← کارت‌ها و حساب‌ها»**: کارت‌های خودش را ثبت می‌کند (صاحب پیش‌فرض خودش است؛
  برای کسی که اپ ندارد «شخص دیگر»). تراکنش‌های هر کارت فقط روی گوشی صاحبش
  ویرایش/دسته‌بندی/حذف می‌شود و بقیه فقط می‌بینند.

## ۴) چه چیزهایی را تست کن
- [ ] ورود با شماره موبایل و رمزی که در پنل ساختی (با رمز غلط: «شماره موبایل یا رمز
      عبور اشتباه است»).
- [ ] «فرستنده‌های پیامک بانک»: پیشنهادها با متن نمونه؛ فرستنده‌ی بانک را مجاز کن →
      پیامک‌های قبلیِ همان فرستنده هم وارد می‌شوند. فرستنده‌ی غیربانکی → «حذف N تراکنش».
- [ ] یک پیامک تبلیغاتیِ مبلغ‌دار بیاید → ثبت **نمی‌شود**.
- [ ] **پیامک وقتی اپ بسته است:** اپ را ببند، یک پیامک بانکی (از فرستنده‌ی مجاز) بیاید،
      پیامک را از صندوق پاک کن، بعد اپ را باز کن → تراکنش هست.
- [ ] بالای صفحه‌ی تراکنش‌ها: تراشه‌های «همه / بابا / مامان / …» → با انتخاب «بابا»
      خالص و درآمد/هزینه‌ی بالا و فهرست فقط مال باباست (در هر دو نما).
- [ ] زیر هر تراکنش متن پیامکش دیده می‌شود (در تنظیمات قابل خاموش کردن)؛ ضربه → جزئیات با
      متن کامل پیامک و دکمه‌ی «حذف (اشتباه/نامعتبر)».
- [ ] بالای صفحه: ماه شمسی + «از ۱ … تا ۳۱ …»؛ فلش راست = ماه قبل.
- [ ] نمای «افراد و کارت‌ها» (پله‌ای) و «همه با هم» (با سرتیتر روز)؛ «ترتیب»؛ «فیلتر».
- [ ] لمس طولانی روی یک تراکنش → انتخاب چندتایی → دسته‌بندی گروهی یا حذف گروهی.
- [ ] «منتظر دسته‌بندی» فقط تراکنش‌های از ۱ مهر ۱۴۰۵ به بعد را نشان دهد (در تنظیمات قابل تغییر).
- [ ] «بازبینی»: فقط پیامک‌های مبهم/ناموفق، با دلیل و متن پیامک.
- [ ] «گزارش و نمودار»: روند روزانه (هزینه/درآمد)، تفکیک افراد/کارت‌ها/دسته‌ها؛ آیکون PDF → اشتراک یا چاپ.
- [ ] «تنظیمات ← همگام‌سازی الان» → پیام «N ارسال، M دریافت». با سرور خاموش → پیام
      «سرور در دسترس نبود…» و تراکنش‌ها در صف می‌مانند؛ سرور را روشن کن و دوباره بزن.
- [ ] گوشی دوم با حساب بابا → تراکنش‌های کارت بابا قابل ویرایش، بقیه با قفل (فقط دیدنی).
- [ ] پنل مدیریت ← «تراکنش‌ها»: تراکنش‌های رسیده از گوشی‌ها دیده می‌شوند؛ عمل «نامعتبر کن»
      آن‌ها را از گوشی‌ها هم حذف می‌کند (در همگام‌سازی بعدی).

## نکته‌ها
- این نسخه برای تست روی شبکه‌ی خانه HTTP بدون TLS را مجاز می‌کند و با کلید debug امضا شده.
  نسخه‌ی تولیدی روی VPS با HTTPS خواهد بود.
- متن پیامک‌ها فقط روی خود گوشی ذخیره می‌شود و هرگز به سرور نمی‌رود (پنل مدیریت هم
  آن را ندارد).
- ساخت دوباره‌ی APK: `cd mobile && flutter build apk --release --split-per-abi`.
- تست زنده‌ی همگام‌سازی با سرور واقعی (دو گوشی شبیه‌سازی‌شده): `mobile/test_live/` — روش
  اجرا در سرِ فایل. دو کاربرِ آزمایشی را روی یک سرورِ جدا (با `SQLITE_PATH` جدا) بساز، نه
  روی دیتابیس اصلی.
